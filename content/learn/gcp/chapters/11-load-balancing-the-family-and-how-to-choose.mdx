## Global or regional

A **global** load balancer has one IP announced from Google's edge locations all over the world (anycast, <Ch course="fundamentals" n="33">Fundamentals ch 33</Ch>). A **regional** one has an IP that belongs to one region and serves backends in that region.

<LbGlobal />

<Table>
  <thead>
    <tr><th>#</th><th>Choose global when</th><th>Choose regional when</th></tr>
  </thead>
  <tbody>
    <tr><td>1</td><td>Users are in several countries</td><td>The service and its users are in one region</td></tr>
    <tr><td>2</td><td>You want routing to the nearest healthy region and failover between regions from one IP</td><td>A rule says traffic must stay in one region, including TLS termination</td></tr>
    <tr><td>3</td><td>You want Cloud CDN, or Cloud Armor edge policies</td><td>You want Standard network tier (<Ch n="3">chapter 3</Ch>), or a simpler model</td></tr>
  </tbody>
</Table>

<Caption>For public web traffic, the global external Application Load Balancer is GCP's normal default. Pick regional on purpose, for a reason.</Caption>

<Key title="Two links back to earlier chapters">

- **Global needs Premium tier.** A global load balancer can only use a global, Premium-tier IP (<Ch n="3">chapter 3</Ch> sections 04 and 05).
- **Envoy-based load balancers need a proxy-only subnet.** Regional external, regional internal and cross-region internal load balancers run Google-managed Envoy proxies inside your VPC, which take their addresses from a subnet with purpose `REGIONAL_MANAGED_PROXY` or `GLOBAL_MANAGED_PROXY` (<Ch n="2">chapter 2</Ch> section 06). The global external one runs on Google Front Ends outside your VPC and needs none.

</Key>

## Proxy or passthrough: the choice that changes behaviour

Does the load balancer end the client's connection and open a new one to the backend, or let the original connection pass straight through? Everything else follows from that.

<ProxyEx />

<Table>
  <thead>
    <tr><th>#</th><th></th><th>Proxy</th><th>Passthrough</th></tr>
  </thead>
  <tbody>
    <tr><td>1</td><td>Connections</td><td>Two: client to load balancer, load balancer to backend</td><td>One: client to backend; the load balancer only steers packets</td></tr>
    <tr><td>2</td><td>Source IP the backend sees</td><td>The load balancer's (`35.191.x.x` or a proxy-only subnet address). Real client in `X-Forwarded-For`</td><td>The real client's</td></tr>
    <tr><td>3</td><td>HTTP routing, TLS termination, WAF, header changes, caching</td><td>Possible, because it has ended the connection and can read it</td><td>Impossible: it never reads the traffic</td></tr>
    <tr><td>4</td><td>Replies</td><td>Go back through the load balancer</td><td>Go straight from the backend to the client (direct server return)</td></tr>
    <tr><td>5</td><td>Protocols</td><td>TCP (and HTTP on top)</td><td>TCP, UDP, and others such as ESP and ICMP</td></tr>
    <tr><td>6</td><td>Layer</td><td>L7 or L4</td><td>Always L4: you cannot read HTTP without ending the connection</td></tr>
  </tbody>
</Table>

<Table>
  <thead>
    <tr><th>#</th><th>You need</th><th>Use</th></tr>
  </thead>
  <tbody>
    <tr><td>1</td><td>HTTP routing, a WAF, TLS termination at the load balancer</td><td>Proxy (an Application Load Balancer)</td></tr>
    <tr><td>2</td><td>The backend to see the real client IP at the network level</td><td>Passthrough</td></tr>
    <tr><td>3</td><td>UDP or another non-TCP protocol</td><td>Passthrough</td></tr>
    <tr><td>4</td><td>The load balancer to stay out of the connection (end-to-end TLS the backend handles)</td><td>Passthrough</td></tr>
  </tbody>
</Table>

<Caption>If you need a WAF in front of a web app, you must use a proxy, and accept that the app reads client IPs from a header (<Ch n="12">chapter 12</Ch> section 06).</Caption>

<Caption>Passthrough load balancers are always regional, and Application load balancers are always proxies. Those two rules explain every combination that does not exist.</Caption>

Choosing is a short walk down four questions:

<LbTree />

<Box kind="exam" title="Exam angle">

The questions usually hide the deciding detail in one phrase: "HTTPS with a WAF" (Application, proxy), "users worldwide, one IP" (global external Application), "UDP" or "must see client IPs" (passthrough Network), "only reachable from the VPC" (internal), "next hop for an appliance" (internal passthrough).

## Back to Kadé

<Box kind="fixed" title="Decided: Kadé keeps a global external Application Load Balancer">

- **HTTPS with a WAF** means Application, which means proxy. A Network load balancer would be cheaper per hour but cannot run Cloud Armor or route by path.
- **External,** because shoppers are on the internet. An internal load balancer would only be useful if Kadé later splits the API into services that call each other.
- **Global,** because Cloud CDN, which serves Kadé's product images (<Ch n="12">chapter 12</Ch>), only works with the global external one, and because it is what Kadé already has. Kadé's users are mostly in Sri Lanka, so the gain from worldwide spread is small, but nothing in Kadé's case calls for regional.
- **The not-classic version,** for the newer routing features. Its IP `34.120.88.10` is already global and Premium tier (<Ch n="3">chapter 3</Ch>), and it needs no proxy-only subnet.
- **Real client IP** comes from `X-Forwarded-For`, read correctly (<Ch n="12">chapter 12</Ch> section 06).

## Commands in this chapter

All read-only.

<TryIt n={1} title="List forwarding rules (the front of every load balancer)">

- **What it shows:** Every load balancer's IP, port, scope and scheme.
- **What to look for:** `EXTERNAL_MANAGED` (the newer global or regional external Application LB), `EXTERNAL` (classic or passthrough), `INTERNAL` or `INTERNAL_MANAGED`.

```sh
gcloud compute forwarding-rules list \
  --format="table(name,region.basename(),IPAddress,portRange,loadBalancingScheme,target.basename())"
```

</TryIt>

<TryIt n={2} title="List backend services">

- **What it shows:** Each backend service with its scheme, protocol and whether it is global.
- **What to look for:** The protocol (`HTTP`, `HTTPS`, `TCP`, `UDP`) tells you L7 or L4.

```sh
gcloud compute backend-services list \
  --format="table(name,region.basename(),loadBalancingScheme,protocol)"
```

</TryIt>

<TryIt n={3} title="List proxy-only subnets">

- **What it shows:** Subnets reserved for Envoy-based load balancers.
- **What to look for:** None for Kadé. One per region is needed before creating a regional or internal Application LB.

```sh
gcloud compute networks subnets list \
  --filter="purpose~MANAGED_PROXY" --format="table(name,region.basename(),ipCidrRange,purpose,role)"
```

</TryIt>

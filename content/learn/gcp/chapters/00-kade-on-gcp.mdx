## One correction first: a VPC has no address range

<Recalls><Recall n="3">Networks, hosts and CIDR</Recall><Recall n="5">The default gateway</Recall></Recalls>

The fundamentals course map said `kade-vpc 10.10.0.0/16`. That was a useful shortcut, but it is not how GCP works. <Term>In GCP, a VPC network has no address range of its own. Only subnets have ranges.</Term> A home router is set up with one LAN range; a VPC is not.

So `10.10.0.0/16` is **Kadé's own plan**: the block we promise to take every subnet range from. GCP does not know about it and does not enforce it. That has three results:

<Table>
  <thead>
    <tr><th>#</th><th>What this means</th><th>Example</th><th>Chapter</th></tr>
  </thead>
  <tbody>
    <tr><td>1</td><td>A subnet can use any private range, even one far outside our plan</td><td>GCP would accept a new subnet `192.168.50.0/24` in kade-vpc</td><td>2</td></tr>
    <tr><td>2</td><td>Two VPCs can use the same ranges, and nothing warns you until you try to connect them</td><td>A staging VPC that also uses `10.10.1.0/24` cannot be peered with kade-vpc</td><td>14</td></tr>

</Box>

**Two rules you cannot see.** Every VPC also has two built-in rules that never show up in this list: block all incoming traffic, and allow all outgoing traffic. Everything above is an exception to the first one. <Ch n="5">Chapter 5</Ch> starts from them.

</Note>

## Commands in this chapter

All read-only. Replace `kade-prod` with your own project ID to run them on a real project.

<TryIt n={1} title="Set the default project">

- **What it shows:** Sets `kade-prod` as the project for every later command.
- **What to look for:** Nothing to check. It only saves typing `--project` each time.

```sh
gcloud config set project kade-prod
```

</TryIt>

<TryIt n={2} title="List the VPC networks">

- **What it shows:** Every VPC network in the project, with its mode (auto or custom).
- **What to look for:** A `default` network that nobody meant to keep, and empty `IPV4_RANGE` columns: a VPC has no range of its own.

```sh
gcloud compute networks list
```

</TryIt>

<TryIt n={3} title="List the subnets of kade-vpc">

- **What it shows:** Each subnet with its region and IP range.
- **What to look for:** Ranges that fit the address plan in section 06, and no overlaps.

```sh
gcloud compute networks subnets list --network=kade-vpc
```

</TryIt>

<TryIt n={4} title="List firewall rules with sources and targets">

- **What it shows:** Every firewall rule with where traffic may come from, which ports it opens, and which VMs it applies to.
- **What to look for:** `0.0.0.0/0` next to admin ports like 22 or 3389, and rules with no target tags, which apply to every VM in the network.

```sh
gcloud compute firewall-rules list \
  --format="table(name,network,sourceRanges.list(),
    allowed[].map().firewall_rule().list(),targetTags.list())"
```

</TryIt>

<TryIt n={5} title="List the VMs">

- **What it shows:** Every VM with its zone, internal IP and external IP.
- **What to look for:** Any external IP that should not be there. In Kadé's project today there are none.

```sh
gcloud compute instances list
```

</TryIt>

<TryIt n={6} title="List reserved static IPs">

- **What it shows:** IP addresses reserved in the project, internal and external.
- **What to look for:** The load balancer IP `34.120.88.10`; from <Ch n="7">chapter 7</Ch>, the NAT IP `34.87.200.7`.

```sh
gcloud compute addresses list
```

</TryIt>

<TryIt n={7} title="List DNS records in the public zone">

- **What it shows:** The records Cloud DNS serves for `kade.lk`.
- **What to look for:** `api.kade.lk` pointing at `34.120.88.10`.

```sh
gcloud dns record-sets list --zone=kade-lk
```

</TryIt>

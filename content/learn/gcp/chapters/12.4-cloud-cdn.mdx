<Box kind="problem" title="The problem">

Cloud CDN was turned on for `kade-static` and `kade-media-backend` with one flag each (<Ch n="12.1">chapters 12.1</Ch> and <Ch n="12.2">12.2</Ch>), and nobody looked at it again. Then three things happen in one week:

- the sale banner is replaced, and shoppers keep seeing the old one;
- `kade-media` is busy all day, although it serves the same few hundred photos;
- someone suggests "just cache the API too, it will be faster".

</Box>

## What a cache does

A <Term>cache</Term> keeps a copy of a response, so the next request for the same thing is answered from the copy. The server that made the original is called the <Term>origin</Term>. For Kadé the origins are the bucket `kade-static-assets` and the `kade-media` VMs.

Every request ends in one of three ways:

<Figure wide hues={["plum", "teal", "green"]} labels={{ plum: "Cloud CDN", teal: "The origin" }} drawing={<FigHitMiss />}>

A **hit** never reaches the origin. A **miss** does, once. How long a copy counts as fresh is its <Term>TTL</Term> (time to live). After that, Cloud CDN asks the origin "has it changed?", which is called **revalidation**: a `304` answer costs almost nothing, because the file itself is not sent again.

</Figure>

## Where Cloud CDN sits

<Recalls><Recall n="33">Proxies and load balancers</Recall></Recalls>

Cloud CDN is not a separate product in front of the load balancer. It is a switch on a **backend service or backend bucket** (link 4 of the chain in <Ch n="12.1">chapter 12.1</Ch>), the same place Cloud Armor attaches. It works only on the external Application Load Balancer, because only a proxy has read the request and the response (<Ch n="11">chapter 11</Ch> section 05).

The copies are kept at Google's edge locations, close to users. **Each location keeps its own cache**:

<Figure wide hues={["plum", "teal", "green"]} labels={{ plum: "Cloud CDN", teal: "The origin" }} drawing={<FigEdges />}>

So "the first request is a miss" is true once per location, not once in the world. A file that few people ask for may never be a hit anywhere.

</Figure>

Where the cache falls among Cloud Armor's checks matters (<Ch n="12.3">chapter 12.3</Ch> section 01): an edge security policy runs **before** the cache, a backend security policy runs **after** it. A cache hit is never seen by `kade-edge-policy`.

## How long it is kept

The origin states a lifetime in the `Cache-Control` header. Cloud CDN adds three settings of its own, which act as a fallback and two caps:

<Figure wide hues={["plum"]} labels={{ plum: "Cloud CDN" }} drawing={<FigTtl />}>

A cap can only shorten what the origin asked for. To keep a file longer, the origin must ask for longer **and** the cap must allow it.

</Figure>

<Table>
  <thead>
    <tr><th>#</th><th>Setting</th><th>Default</th><th>What it does in `CACHE_ALL_STATIC`</th></tr>
  </thead>
  <tbody>
    <tr><td>1</td><td>**Default TTL**</td><td>1 hour</td><td>Used when the origin gives no lifetime</td></tr>
    <tr><td>2</td><td>**Max TTL**</td><td>1 day</td><td>Caps how long the edge keeps a copy</td></tr>
    <tr><td>3</td><td>**Client TTL**</td><td>1 hour</td><td>Caps how long browsers are told to keep it</td></tr>
  </tbody>
</Table>

<Caption>In `USE_ORIGIN_HEADERS` none of the three apply: the origin's header is followed as it is. In `FORCE_CACHE_ALL` the default TTL and client TTL replace the origin's header.</Caption>

The parts of `Cache-Control` worth knowing:

<Table>
  <thead>
    <tr><th>#</th><th>The origin sends</th><th>Meaning</th></tr>
  </thead>
  <tbody>
    <tr><td>1</td><td>`public, max-age=86400`</td><td>Anyone may keep it, for a day</td></tr>
    <tr><td>2</td><td>`s-maxage=600`</td><td>A lifetime for shared caches such as Cloud CDN only. It wins over `max-age` there</td></tr>
    <tr><td>3</td><td>`private`</td><td>Only the shopper's own browser may keep it. Not stored at the edge</td></tr>
    <tr><td>4</td><td>`no-store`</td><td>Nobody keeps it. Kadé's API sends this on everything</td></tr>
    <tr><td>5</td><td>`immutable`</td><td>This URL's content will never change, so browsers need not re-check it</td></tr>
  </tbody>
</Table>

## The cache key

When a request arrives, Cloud CDN has to decide whether it already holds "the same thing". It does that by building a <Term>cache key</Term> from the request and looking the key up. Two requests with the same key share one stored copy.

For a backend service, the default key is the whole URL:

<Figure wide hues={["amber"]} labels={{ amber: "The part you usually change" }} drawing={<FigKey />} />

The query string is where this goes wrong, in both directions. `kade-media` can return another file format with `?fmt=`, and marketing adds `?utm_source=` to every link:

<CdnKey />

<Key title="The rule for a cache key">

Put in everything that changes the response, and nothing else. Too much in the key wastes the cache. Too little serves the wrong response.

</Key>

## Changing a file

This is the stale banner from the top of the chapter. After `banner.jpg` is replaced in the bucket, the old copy still exists in two kinds of place, and you can only reach one of them:

## When the origin is slow or down

A copy does not have to be thrown away the second it expires. Two settings make the cache carry on when the origin cannot:

<Figure wide drawing={<FigStale />}>

**Serve while stale**: for a set time after the TTL, shoppers get the old copy at once while Cloud CDN fetches a fresh one behind them. If the origin is failing, they keep getting the old copy.

</Figure>

**Negative caching** stores error answers too, for a short time. Without it, every request for a photo that does not exist is a miss, and a bot asking for thousands of missing files reaches `kade-media` with every one. With it, the `404` is answered from the edge for a minute or two.

<Note>

Negative caching has a cost: a file uploaded one second after someone asked for it stays "not found" until the stored `404` runs out. Keep that lifetime short.

</Note>

## Private files

Cloud CDN is built for files anyone may read. Some files are not: an invoice, a paid download. For these the app hands out a <Term>signed URL</Term>, a link that carries an expiry time and a signature made with a key only the app and Cloud CDN know:

<Figure wide hues={["amber", "teal", "green"]} labels={{ amber: "Cloud CDN checks the link", teal: "The origin" }} drawing={<FigSigned />}>

The bucket itself is private. Only Cloud CDN's own service account may read it, so the signed link is the only way in.

</Figure>

## The trap: caching personal data

"Cache the API too" is how this happens. The cache key is the URL. It does not include the cookie or the login token, so two shoppers asking for `/api/orders` have the **same key**:

<Figure wide hues={["plum", "green"]} labels={{ plum: "Cloud CDN and kade-api" }} drawing={<FigLeak />}>

Nothing is broken and nothing is logged as an error. One shopper simply sees another's orders.

</Figure>

<Key title="Before turning on Cloud CDN for a backend">

Ask: does any response from this backend depend on **who** is asking? If yes, leave CDN off, or use `USE_ORIGIN_HEADERS` and have the app mark only the shared responses as `public`.

</Key>

<Table>
  <thead>
    <tr><th>#</th><th>Trap</th><th>What happens</th><th>Avoid it by</th></tr>
  </thead>
  <tbody>
    <tr><td>1</td><td>`FORCE_CACHE_ALL` on an app</td><td>One shopper's page is served to another</td><td>Only ever on a backend of public files</td></tr>
    <tr><td>2</td><td>Replacing a file under the same name</td><td>Old copies live on in browsers, out of reach</td><td>Versioned names (section 06)</td></tr>
    <tr><td>3</td><td>The whole query string in the key</td><td>Tracking parameters split the cache</td><td>An include list (section 05)</td></tr>
    <tr><td>4</td><td>A `Set-Cookie` or `Vary: Cookie` on static files</td><td>Nothing is cached, with no error</td><td>Checking the response headers (command 3)</td></tr>
    <tr><td>5</td><td>Relying on the backend policy for cached content</td><td>A blocked address still gets cache hits</td><td>An edge security policy (<Ch n="12.3">chapter 12.3</Ch> section 01)</td></tr>
    <tr><td>6</td><td>Long negative caching</td><td>A new file stays "not found"</td><td>A minute or two, not hours</td></tr>
    <tr><td>7</td><td>Invalidating on every deploy</td><td>Slow deploys, rate limits, and browsers still stale</td><td>Versioned names</td></tr>
  </tbody>
</Table>

<Box kind="cost" title="Cost and limits (checked November 2026)">

Cloud CDN bills for data served from the cache, data fetched from the origin to fill it, and a small amount per lookup. Cached data usually costs less than the same data served from the origin, so a good hit ratio lowers the bill as well as the load. Invalidations are billed each and rate limited. Check the Cloud CDN pricing page for the current numbers.

</Box>

<Box kind="exam" title="Exam angle">

"Serve static files faster worldwide" is Cloud CDN on a backend bucket. "Cache only what the app marks cacheable" is `USE_ORIGIN_HEADERS`. "Users see old content after a deploy" is versioned file names, or an invalidation for a one-off. "Keep serving when the origin is down" is serve while stale. "Time-limited access to a private file" is a signed URL. "Low hit ratio with many URL parameters" is the cache key.

</Box>

## Back to Kadé

<Box kind="fixed" title="Fixed: three backends, three answers">

- **The stale banner.** The build now puts a hash in every file name under `/assets/`, and those files are cached for a year. `index.html` keeps its name and is cached for five minutes. One invalidation cleared the old banner from the edge.
- **The busy kade-media.** Its cache key now holds only `fmt` from the query string, so tracking parameters no longer cause misses. Serve while stale and negative caching are on.
- **"Cache the API too".** No. `kade-api-backend` stays without CDN, and the API keeps sending `no-store`.

### The CDN settings as Terraform

```hcl
resource "google_compute_backend_bucket" "kade_static" {
  name        = "kade-static"
  bucket_name = "kade-static-assets"
  enable_cdn  = true

  cdn_policy {
    cache_mode        = "CACHE_ALL_STATIC"
    default_ttl       = 3600
    max_ttl           = 31536000
    client_ttl        = 31536000
    serve_while_stale = 86400
    negative_caching  = true
  }
}

resource "google_compute_backend_service" "kade_media" {
  name       = "kade-media-backend"
  enable_cdn = true
  # backend, health check, security policy and logging: chapter 12.2

  cdn_policy {
    cache_mode        = "CACHE_ALL_STATIC"
    default_ttl       = 3600
    max_ttl           = 86400
    client_ttl        = 3600
    serve_while_stale = 86400
    negative_caching  = true

    negative_caching_policy {
      code = 404
      ttl  = 60
    }

    cache_key_policy {
      include_protocol       = true
      include_host           = true
      include_query_string   = true
      query_string_whitelist = ["fmt"]
    }
  }
}
```

<TryIt n={2} title="See hits and misses in the logs">

- **What it shows:** Recent requests to kade-media, with what the cache did for each.

<TryIt n={3} title="Read the headers of one response">

<TryIt n={6} title="Keep only fmt in the cache key (changes the project)">

- **What it shows:** Section 05's fix for kade-media.

<TryIt n={7} title="Set Cache-Control on files in the bucket (changes the project)">

- **What it shows:** The lifetime each kind of file asks for.
- **What to look for:** The new `cache-control` line in command 3. Set it in the upload step of the build, so new files get it too.

```sh
gcloud storage objects update "gs://kade-static-assets/assets/**" \
```

</TryIt>

<TryIt n={8} title="Invalidate cached copies (changes the project)">

- **What it shows:** Every edge location dropping its copies of the matching paths.
- **What to look for:** The next request is a miss. Browsers that already hold the file are not affected. A `*` is allowed only at the end of the path.

```sh
gcloud compute url-maps invalidate-cdn-cache kade-url-map \
  --host=www.kade.lk --path="/images/banner.jpg"
gcloud compute url-maps invalidate-cdn-cache kade-url-map \
  --host=www.kade.lk --path="/images/*"
```

</TryIt>

## Measure your own real timings

A model is useful; a measurement is better. `curl` can print when each phase finished:

```sh
curl -so /dev/null -w 'dns %{time_namelookup}\nconnect %{time_connect}\ntls %{time_appconnect}\nttfb %{time_starttransfer}\ntotal %{time_total}\n' https://www.google.com
```

Run it twice (the second run usually has DNS cached), against any HTTPS site, and paste the output here:

<CurlTime />

<Note>

**The same numbers in the browser.** DevTools → Network → click a request → **Timing**. "DNS Lookup", "Initial connection", "SSL", "Waiting for server response" (TTFB) and "Content Download" are exactly the phases above. A reused connection shows no DNS, connection or SSL rows at all.

</Note>

## When it breaks: a map of where to look

Every step is also a place where things fail. Find the symptom, and you know the layer and the chapter:

<Table>
  <thead>
    <tr><th>#</th><th>Step</th><th>Symptom</th><th>Likely cause</th><th>Check with</th><th>Ch</th></tr>
  </thead>
  <tbody>
    <tr><td>1</td><td>DHCP</td><td>Address 169.254.x.x; "no internet"</td><td>No DHCP server reply</td><td>`ipconfig getifaddr en0`</td><td>27</td></tr>
    <tr><td>2</td><td>ARP / gateway</td><td>Can't even ping 192.168.1.1</td><td>WiFi, cable, wrong network</td><td>`arp -a`, `ping 192.168.1.1`</td><td>5, 9</td></tr>
    <tr><td>3</td><td>DNS</td><td>"Could not resolve host" / NXDOMAIN / SERVFAIL</td><td>Missing record, broken DNSSEC, resolver down</td><td>`dig api.kade.lk`, `dig @8.8.8.8 …`</td><td>22-23</td></tr>
    <tr><td>4</td><td>Routing</td><td>Timeouts; traceroute stops at one hop</td><td>A route or peering problem</td><td>`traceroute -T -p 443 api.kade.lk`</td><td>12-13</td></tr>
    <tr><td>5</td><td>TCP</td><td>"Connection refused" vs "timed out"</td><td>Nothing listening vs firewall drop</td><td>`nc -vz api.kade.lk 443`</td><td>16, 31</td></tr>
    <tr><td>6</td><td>MTU</td><td>Handshake works, big responses hang</td><td>PMTUD black hole (VPNs)</td><td>`ping -D -s 1472 …`</td><td>18</td></tr>
    <tr><td>7</td><td>TLS</td><td>Certificate errors; handshake failure</td><td>Expired cert, wrong name, missing chain, TLS inspection</td><td>`openssl s_client -connect api.kade.lk:443 -servername api.kade.lk`</td><td>25</td></tr>
    <tr><td>8</td><td>Browser rules</td><td>Works in curl, fails in the browser</td><td>CORS, mixed content, HSTS</td><td>DevTools console</td><td>28</td></tr>
    <tr><td>9</td><td>Load balancer</td><td>502 / 503 / 504</td><td>Keep-alive race, no healthy backend, timeout</td><td>LB logs `statusDetails`, `get-health`</td><td>33</td></tr>
    <tr><td>10</td><td>App</td><td>500, 401, 404</td><td>Your code, auth, routes</td><td>App logs (with the real client IP, thanks to trust proxy)</td><td>24</td></tr>
    <tr><td>11</td><td>Speed</td><td>Slow but working</td><td>Round trips, loss, bufferbloat, no connection reuse</td><td>`curl -w` (section 5), `mtr`</td><td>13, 20, 21</td></tr>
  </tbody>
</Table>

<Caption>Work from the bottom up: if `ping 192.168.1.1` fails, nothing above it matters yet. Each passing check clears a whole layer.</Caption>

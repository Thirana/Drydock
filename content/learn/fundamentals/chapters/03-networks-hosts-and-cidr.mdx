## What a network is

A <Term>network</Term> is a set of devices connected so they can talk to each other. Your home WiFi is one: the laptop, phone, smart TV and printer, all joined through the home router.

<Figure wide hues={["plum", "teal", "green"]} drawing={<FigNetwork />} />

Devices on the same network reach each other directly. When you print a Kadé invoice, the laptop sends it straight to the printer. Reaching anything outside, like api.kade.lk, means leaving the network through the router. <Ch n="4">Chapter 4</Ch> shows how the laptop decides which case it is in.

## Hosts

A <Term>host</Term> is any single device on a network that has its own IP address. The home network above has five hosts: the four devices and the router itself (192.168.1.1). In the cloud, kade-api and kade-db are hosts on kade-vpc.

Each host needs a unique address on its network, so data is delivered to exactly the right one. If two devices end up with the same address (an IP conflict), both start losing their connections.

## How devices get their IP: DHCP

You never type these addresses in. When a device joins, the router hands it one using <Term>DHCP</Term> (Dynamic Host Configuration Protocol). It takes four messages, often remembered as **DORA**:

<Figure wide hues={["plum", "teal", "green", "amber"]} drawing={<FigDhcp />}>

Dashed amber = broadcast (sent to every device). The laptop has no address yet, so it can only shout. Leases are renewed quietly, usually at half the lease time.

</Figure>

The Offer carries more than an address. It gives the laptop everything it needs to use the network, and every item shows up again later in the course:

<Note>

**Reserved vs static.** The laptop must find the printer at the same address every time, so the router is told "always give MAC 00:1b:a9:44:7c:21 the address .60". That is a **reservation**: the address still comes from DHCP. A **static** address is typed into the device itself, and DHCP is not used. GCP works the same way: kade-api gets 10.10.1.10 from GCP's DHCP, and you can reserve it as a static internal IP.

</Note>

## LAN and WAN

The home network is a <Term>LAN</Term> (Local Area Network): devices in one place, on one network. Everything beyond it, the ISP and the wider internet, is the <Term>WAN</Term> (Wide Area Network). Most of networking is about how a device on your LAN reaches something out on the WAN.

<Figure wide hues={["teal", "green"]} drawing={<FigLanwan />}>

The router stands on both sides and has two addresses. The ISP gives it the WAN address, also with DHCP. The internet only ever sees 203.0.113.45, never 192.168.1.x.

</Figure>

## CIDR notation

To describe a whole network we need a way to name a range of addresses. <Term>CIDR</Term> (Classless Inter-Domain Routing) does it in one short line: an IP, a slash, and a number. The home network is `192.168.1.0/24`.

<CidrBar ip="192.168.1.0" prefix="24" />

- **The /24** is how many bits, counted from the left, form the network part. The rest are the host part.
- **The .0 address** is the <Term>network address</Term>: the name of the network as a whole. Keep the network bits and set every host bit to 0, and you get it: `192.168.1.0`. Routes and firewall rules use it to mean "this whole network". It is never given to a device.
- **The .255 address** is the <Term>broadcast address</Term>: set every host bit to 1 instead. A message sent to it reaches every device on this network. It is not given to a device either.

You will also meet the same split written a second way, as a **subnet mask**. For a /24 it is `255.255.255.0`: 24 ones, then 8 zeros, written like an address. It is what your laptop got from DHCP (above). <Ch n="4">Chapter 4</Ch> shows how a device uses it to decide where to send each packet.

In 192.168.1.0/24, the first 24 bits (three octets: 8 + 8 + 8) are the network part. They are the same for every device on the network. The last 8 bits (the last octet) are the host part, different for each device:

  <tbody>
    <tr><td>Laptop</td><td><Mono>192.168.1.23</Mono></td><td>same network, host 23</td></tr>
    <tr><td>Phone</td><td><Mono>192.168.1.40</Mono></td><td>same network, host 40</td></tr>
    <tr><td>Printer (new)</td><td><Mono>192.168.1.60</Mono></td><td>plugged in today: network part unchanged, only the host part is new</td></tr>
  </tbody>
</Table>

<Key title="Rule of thumb">

Network bits are fixed across the whole network. Host bits are free to change per device.

</Key>

## How many hosts fit

The number of host bits decides how many addresses the network has. With 8 host bits (a /24), there are 2<sup>8</sup> = 256 addresses. Two of them are reserved (network and broadcast), which leaves 254 for devices, and the router takes one of those.

<Range>
  <RangePart kind="special" w="13%" sub="network">.0</RangePart>
  <RangePart kind="router" w="13%" sub="router">.1</RangePart>
  <RangePart kind="devices" sub="devices: .23 laptop, .40 phone, .52 TV, .60 printer">.2 to .254</RangePart>
  <RangePart kind="special" w="13%" sub="broadcast">.255</RangePart>
</Range>

<Caption>Many routers hand out only part of this, for example .100 to .200, to leave room for fixed devices.</Caption>

<Key title="The formula">

Addresses = 2<sup>host bits</sup> = 2<sup>(32 − prefix)</sup>. Usable for devices = that number − 2. When every address is taken, the next device to join gets no IP: the network is full.

</Key>

## Reading CIDR ranges

A smaller number after the slash means fewer network bits, more host bits and a bigger network.

## CIDR in the cloud

CIDR is used everywhere in cloud work. When kade-vpc was created, its range was chosen with CIDR: `10.10.0.0/16`. That range holds 256 blocks of /24, and Kadé uses two of them as subnets:

<VpcSlots />

Subnets inside one VPC must not overlap. GCP also keeps 4 addresses in every subnet for itself, not 2:

  <thead>
    <tr><th>sn-app address</th><th>Kept for</th></tr>

    <tr><td><Mono>10.10.1.1</Mono></td><td>The default gateway for VMs in this subnet</td></tr>

  </tbody>

<Caption>So a /24 subnet in GCP has 256 − 4 = 252 usable addresses. kade-api's 10.10.1.10 is one of them.</Caption>

Type any range. The calculator shows its network address, the same range as a subnet mask, its broadcast address, and how many addresses are left for devices: at home, and in a GCP subnet, where 4 are kept.

<CidrCalc cidr="10.10.1.0/24" />

<Note>

**Plan ranges early.** Two networks can only be joined (by VPN or peering) if their ranges do not overlap. kade-vpc (10.10.0.0/16) and the future Kadé office (172.16.0.0/16) are safe. If the VPC had been created as 192.168.0.0/16, it would clash with most home and office networks.

</Note>

## Try it yourself

<TryIt n={1} title="The DHCP answer your laptop got">

- **What to look for:** `yiaddr` (your IP), `router`, `subnet_mask`, `domain_name_server`, `lease_time`.
- **Runs on:** macOS · Windows: ipconfig /all · Linux: nmcli device show
- **From section:** [3. How devices get their IP: DHCP](#how-devices-get-their-ip-dhcp)

```sh
ipconfig getpacket en0
```

</TryIt>

<TryIt n={2} title="Run DHCP again">

- **What to look for:** Usually the same IP comes back: the router remembers your MAC.
- **Runs on:** macOS · Windows: ipconfig /release then ipconfig /renew
- **From section:** [3. How devices get their IP: DHCP](#how-devices-get-their-ip-dhcp)

```sh
sudo ipconfig set en0 DHCP
```

</TryIt>

<TryIt n={3} title="Other hosts your laptop has talked to on the LAN">

- **What to look for:** Their IPs and MACs, all in 192.168.1.x.
- **From section:** [2. Hosts](#hosts)

```sh
arp -a
```

</TryIt>

<TryIt n={4} title="Your IP with its prefix">

- **What to look for:** `192.168.1.23/24` and the word `dynamic` (from DHCP).
- **Runs on:** Linux

ip -4 addr

</TryIt>

## Two parts: header and data

A UDP datagram is an **8-byte header** followed by your data, the <Term>payload</Term>. The header has four fields of 2 bytes (16 bits) each. Protocol diagrams draw headers in rows 32 bits wide:

## Field 1 · Source port (2 bytes)

Identifies the sending application, so replies find their way back to the right program. Here: `c7 38` = 0xC738 = **51000**, a temporary port the OS picked for this lookup (<Ch n="1">chapter 1</Ch> called it an ephemeral port).

The source port is **optional** in UDP: it may be 0 when no reply is expected. In practice almost every app fills it in.

## Field 2 · Destination port (2 bytes)

Says which application on the receiving machine should get the datagram. Here: `00 35` = 0x0035 = **53**, the DNS service. Ports are how one IP address can run many services at once: the router answers DNS on 53 and DHCP on 67 at the same time.

2 bytes = 16 bits, so ports go from 0 to 65,535. They are grouped by convention:

    <tr><td>2</td><td>`1024–49151`</td><td>Registered</td><td>Services registered by apps (e.g. 3478 STUN, 5432 PostgreSQL)</td></tr>
    <tr><td>3</td><td>`49152–65535`</td><td>Ephemeral (dynamic)</td><td>Temporary client ports. Linux actually uses 32768-60999 by default.</td></tr>
  </tbody>
</Table>

## How the port picks the program

When a datagram arrives, the OS looks at its destination IP and port and finds the program that opened a <Term>socket</Term> on that port. This sorting is called <Term>demultiplexing</Term>. On the router:

<Table>
  <thead>
    <tr><th>Datagram to port</th><th>Socket open?</th><th>Result</th></tr>
  </thead>
  <tbody>
    <tr><td><Mono>53</Mono></td><td>yes: DNS service</td><td>Payload handed to the DNS service</td></tr>
    <tr><td><Mono>67</Mono></td><td>yes: DHCP server</td><td>Handed to the DHCP server</td></tr>
    <tr><td><Mono>33434</Mono></td><td>no</td><td>Dropped; the OS sends back ICMP "port unreachable" (type 3, code 3). This is how traceroute's last hop answers (<Ch n="13">chapter 13</Ch>).</td></tr>
  </tbody>
</Table>

## Field 3 · Length (2 bytes)

The size of the **whole datagram**, header plus data, in bytes. Here: `00 25` = 0x0025 = **37** = 8 header + 29 data. The minimum is 8 (a header with no data). The maximum is 65,535, though <Ch n="14">chapter 14</Ch> explained why real datagrams stay far smaller.

The IP header also carries a total length, so this field is technically redundant over IPv4. It makes UDP self-describing: its header alone says where its data ends.

## Field 4 · Checksum (2 bytes)

An error-detection code. Here: `ec 99`. The receiver recomputes it and, if it does not match, silently throws the datagram away (UDP never asks for a resend).

The checksum covers three things: the UDP header, the data, and a <Term>pseudo-header</Term>, a few fields borrowed from the IP header that are never sent as part of UDP:

<Table>
  <thead>
    <tr><th>Pseudo-header field</th><th>Value</th><th>Bytes</th></tr>
  </thead>
  <tbody>
    <tr><td>Source IP</td><td><Mono>192.168.1.23</Mono></td><td><Mono>c0 a8 01 17</Mono></td></tr>
    <tr><td>Destination IP</td><td><Mono>192.168.1.1</Mono></td><td><Mono>c0 a8 01 01</Mono></td></tr>
    <tr><td>Zero, then protocol</td><td><Mono>0, 17 (UDP)</Mono></td><td><Mono>00 11</Mono></td></tr>
    <tr><td>UDP length</td><td><Mono>37</Mono></td><td><Mono>00 25</Mono></td></tr>
  </tbody>
</Table>

<Caption>Why include IP fields? So a datagram that reaches the wrong address, or is mistaken for another protocol, fails the check. It is also why NAT must recompute the UDP checksum when it rewrites an IP or port (<Ch n="10">chapter 10</Ch>).</Caption>

How it is computed, with our real numbers:

<Table>
  <tbody>
    <tr><td><Mono>1</Mono></td><td>Put the checksum field to 0. Split pseudo-header + header + data into 16-bit chunks (pad with one zero byte if the length is odd).</td><td><Mono>38 bytes + pad</Mono></td></tr>
    <tr><td><Mono>2</Mono></td><td>Add all the chunks together.</td><td><Mono>0x4\_1362</Mono></td></tr>
    <tr><td><Mono>3</Mono></td><td>Fold: add the part that overflowed past 16 bits back into the low 16 bits (0x1362 + 0x4).</td><td><Mono>0x1366</Mono></td></tr>
    <tr><td><Mono>4</Mono></td><td>Flip every bit (ones' complement).</td><td><Mono>0xEC99</Mono></td></tr>
    <tr><td><Mono>✓</Mono></td><td>The receiver adds everything **including** 0xEC99. A clean datagram always gives 0xFFFF.</td><td><Mono>0xFFFF</Mono></td></tr>
  </tbody>
</Table>

<Note>

**Optional, and weak.** Over IPv4 the checksum is optional: 0 means "not used" (so a real result of 0 is sent as 0xFFFF). Over IPv6 it is mandatory, because IPv6 dropped its own header checksum. It is a simple 16-bit sum, so some errors (like two swapped chunks) slip past it. Links add stronger checks (the frame's FCS), and TLS adds cryptographic ones.

</Note>

## Add it up

<Equation>2 src port + 2 dst port + 2 length + 2 checksum = 8 bytes</Equation>

That tiny, fixed header is exactly why UDP is so light. Here is our DNS question as it goes out on the WiFi, all layers together:

## Try it yourself

<TryIt n={1} title="Real DNS datagrams in hex">

- **Steps:** `sudo tcpdump -n -X -i en0 udp port 53`, then `dig example.com` in another terminal
- **What to look for:** After the 20-byte IP header: your source port, `0035`, the length, the checksum, then the name as `07 example 03 com`.
- **From section:** [2. The datagram we will open](#the-datagram-we-will-open)

```sh
sudo tcpdump -n -X -i en0 udp port 53
dig example.com
```

</TryIt>

<TryIt n={2} title="Checksum checks">

- **What to look for:** `[udp sum ok]` on received packets. Sent packets may say "bad" because the network card fills the checksum in after tcpdump sees them (checksum offload).
- **From section:** [7. Field 4 · Checksum (2 bytes)](#field-4-checksum-2-bytes)

```sh
sudo tcpdump -n -vv -i en0 udp port 53
```

</TryIt>

<TryIt n={3} title="A datagram to a closed port">

- **Runs on:** with tcpdump -i lo0 icmp running (Linux: -i lo)
- **From section:** [5. How the port picks the program](#how-the-port-picks-the-program)

```sh
nc -u 127.0.0.1 9
```

</TryIt>

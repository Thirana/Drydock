## What an IP address is

IP stands for Internet Protocol, one of the most important protocols on the internet. An <Term>IP address</Term> is the number a device uses to be found on a network. Every device that wants to talk on a network needs one.

One detail the short definition hides: an IP address belongs to a <Term>network interface</Term>, not to the whole device. An interface is one connection point: the WiFi card, an Ethernet port, or a virtual one made by the OS. Your laptop has several:

## Dotted-quad notation

An IPv4 address is written as four whole numbers separated by dots, in the form A.B.C.D. This is called <Term>dotted-quad</Term> (or dotted-decimal) notation. Four numbers, three dots.

<IpAnatomy ip="192.168.1.23" />

Each number is called an <Term>octet</Term>, so 192.168.1.23 has four. You will often hear "the first three octets" and "the last octet". On the home network, the first three octets (192.168.1) are the same for every device, and only the last octet changes: .23 for the laptop, .40 for the phone, .52 for the TV. <Ch n="3">Chapter 3</Ch> explains why: an address is split into a network part and a host part.

## Why "octet": binary in two minutes

Humans read decimal (192). Computers store <Term>binary</Term>: only 0 and 1. Each 0 or 1 is one <Term>bit</Term>. Each octet is stored in 8 bits, and "octet" simply means a group of eight.

In binary, each position has a value that doubles from right to left: 1, 2, 4, 8, 16, 32, 64, 128. A 1 means "count this position". Add up the positions that hold a 1 and you get the decimal number. Here is the laptop's address, octet by octet:

<PlaceValue values="192,168,1,23" />

<Key title="Decimal to binary, by hand">

Go left to right. If the number is at least the place value, write 1 and subtract it. Otherwise write 0. For 23: 128 no, 64 no, 32 no, 16 yes (7 left), 8 no, 4 yes (3 left), 2 yes (1 left), 1 yes. Result: 00010111.

</Key>

## Why each octet is 0 to 255

The smallest 8-bit value is 00000000, which is 0. The largest is 11111111, which is 128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = 255. So one octet can hold 256 different values, from 0 to 255. That is why 192.168.1.300 is not a valid address: 300 needs 9 bits.

Try any address below. Each octet is shown in binary and in hex.

## 32 bits = 4 bytes

Now the key fact. There are 4 octets and each is 8 bits:

<Equation>4 octets × 8 bits = 32 bits = 4 bytes</Equation>

This links back to <Ch n="1">chapter 1</Ch>. When the IP layer wraps a packet, the source and destination address fields are exactly these 4 bytes each. The laptop 192.168.1.23 is stored as `C0 A8 01 17`, and kade-api 34.87.120.15 as `22 57 78 0F`.

32 bits give 2<sup>32</sup> = 4,294,967,296 possible addresses, about 4.3 billion. That sounds like a lot, but it is fewer than the number of people on Earth, and many people have a phone, a laptop and more. Large blocks are also set aside for special jobs (section 7). IPv4 addresses ran out.

## Running out, and IPv6

The internet dealt with the shortage in two ways. The short-term fix: **private addresses** that many networks can reuse, plus **NAT** at the router to share one public address (both covered later). The long-term fix: <Term>IPv6</Term>, a new address format with a far bigger space.

## Special address ranges

Not every address can be used for anything. Some ranges have fixed jobs. They are written in CIDR form, like 10.0.0.0/8, which <Ch n="3">chapter 3</Ch> explains. For now, read 10.0.0.0/8 as "every address that starts with 10".

<Key title="Private vs public">

The same private address, 192.168.1.23, exists in millions of homes at once. That works because private addresses never travel on the internet: the home router swaps them for its public address first (NAT, a later chapter). A public address must be unique in the whole world.

</Key>

## Try it yourself

<TryIt n={1} title="Your IP on WiFi">

- **What to look for:** Something like 192.168.x.x: a private address.
- **Runs on:** macOS · Linux: hostname -I · Windows: ipconfig
- **From section:** [1. What an IP address is](#what-an-ip-address-is)

```sh
ipconfig getifaddr en0
```

</TryIt>

<TryIt n={2} title="All your interfaces">

- **What to look for:** lo / lo0 with 127.0.0.1, your WiFi with its IP, unplugged ones with no `inet` line.
- **Runs on:** macOS · Linux: ip -4 addr · Windows: ipconfig /all
- **From section:** [1. What an IP address is](#what-an-ip-address-is)

```sh
ifconfig
```

</TryIt>

<TryIt n={3} title="Loopback">

- **What to look for:** Replies even with WiFi off. The packet never leaves the laptop.
- **Runs on:** Windows: ping 127.0.0.1
- **From section:** [7. Special address ranges](#special-address-ranges)

```sh
ping -c 3 127.0.0.1
```

</TryIt>

<TryIt n={4} title="Your public IP, as the internet sees it">

- **What to look for:** Different from your local IP. The router swapped it (NAT).
- **From section:** [7. Special address ranges](#special-address-ranges)

```sh
curl ifconfig.me
```

</TryIt>

<TryIt n={5} title="Decimal to binary">

- **What to look for:** `11000000`
- **Runs on:** macOS / Linux
- **From section:** [3. Why "octet": binary in two minutes](#why-octet-binary-in-two-minutes)

```sh
echo "obase=2; 192" | bc
```

</TryIt>

<TryIt n={6} title="The 4 bytes of the address">

- **What to look for:** `C0 A8 01 17`
- **Runs on:** macOS / Linux
- **From section:** [5. 32 bits = 4 bytes](#32-bits-4-bytes)

```sh
printf '%02X ' 192 168 1 23
```

</TryIt>

<TryIt n={7} title="The VM's internal IP, from the metadata server">

- **What to look for:** On kade-api this returns 10.10.1.10.
- **Runs on:** run on a GCP VM
- **From section:** [7. Special address ranges](#special-address-ranges)


</TryIt>
